Version 2025.2 of %product% contains several updates.

## Native mode updates

As of version 2025.2, %product% provides [native mode](deploy-qodana.md#deploy-qodana-native-mode) for the following linters:

* [%jvm%](jvm.md)
* [%jvm-co%](jvm.md)
* [%php%](php.md)
* [%js%](js.md)
* [%dotnet%](dotnet.md)
* [%python%](python.md)
* [%python-co%](python.md)
* [%go%](golang.md)

## CLI option changes

Version 2025.2 of %product% introduces the following CLI options:

| Option                                                                                                   | Description                                                                                                                      | Usage example                    |
|----------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------|----------------------------------|
| [`--image <image-name>`](docker-image-configuration.topic#docker-config-reference-qodana-scan)           | Specify the Docker image of %product%. Replacement for the `-l, --linter` option. Lets you run custom Docker images of %product% | `--image jetbrains/%jvm-linter%` |
| [`--within-docker <true\|false>`](docker-image-configuration.topic#docker-config-reference-qodana-scan)  | Specify Docker invocation. If set to `false`, it enables [native mode](deploy-qodana.md#deploy-qodana-native-mode)                             | `--within-docker false`          |

The existing `-l,--linter` option lets you specify one of the existing %product% [linters](linters.md) either in native or
in container mode depending on the `--within-docker` option.

## Taint analysis improvements

Version 2025.2 of %product% introduces significant enhancements to the performance and accuracy of the taint analysis engine.

Performance improvements include the following:

* A lightweight distributive reachability analysis (IFDS) now runs as a preprocessing step. It checks the presence of any potential paths from sources to sinks within current scopes.
* Analysis optimization for functions that have no paths.
* The IFDS algorithm operates in linear time and is field-sensitive, call-sensitive, and flow-sensitive.

Accuracy improvements include the following:

* Analysis capabilities for codebases containing seven million lines of code in just under half an hour.
* IFDS improves the quality of reported paths, making them linear and unambiguous.
* Fixing many false positives and false negatives.
* The overall analysis is now both faster and more accurate.

### Improved trace UI

Besides these improvements, the **Security analysis** tab of IntelliJ IDEA now provides improved UI that lets you
improve trace readability, support more efficient navigation, and provide more information about traces. More details
are available in the [](taint-analysis.md) section.
