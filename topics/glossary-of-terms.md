# Frequently-used terms

This section lists common terms related to %product% in alphabetical order.

**A**

**Account in %cloud%** is a user account that lets a user explore analysis reports, manage access to them.

**Analysis or code analysis** is an action performed by [%product%](#qodana) when a specific codebase is analyzed for the presence of
problems using inspections.

**Analysis in CI/CD pipelines** is an analysis performed on a server using CI/CD tools.

**Analysis report** is a description of problems found by [%product%](#qodana) as a result of analysis. Generated and shown as a web page or SARIF-formatted file.

**B**

**Baseline** is a [%product%](#qodana) [feature](baseline.topic) that lets you configure a set of code problems to ignore to focus on new problems.

**C**

**CI/CD support** is an option to add [%product%](#qodana) capabilities to CI/CD pipelines.
{id="ci-cd-support"}

**Community linter** is a linter that does not require a paid [%product%](#qodana) license. However, it still requires a project token.

**Contributor** is a person or a bot who commits code changes to a source code repository that [%product%](#qodana) analyzes.

**D**

**Deployment** is a process of setting up [%product%](#qodana) either [locally](#local-analysis) or in a CI/CD pipeline of a user's choice.

**Docker mode** is an option to analyze code using an available Docker image.

**I**

**IDE support** is an option to use [%product%](#qodana) in [JetBrains IDEs](Quick-start.topic#quickstart-run-in-ide), integrated into the **Problems** tab.

**Insights** is a [feature](insights.md) that aggregates analysis reports across some or all of an organization's projects.

**Inspection** is a software component that lets [%product%](#qodana) analyze a codebase for the presence of specific problems the inspection should reveal.

**L**

**Linter** is a [%product%](#qodana) software component that performs inspections aimed at a specific programming language or technology.

**Local analysis** is an analysis performed on a local user's computer using either user's IDE or a CLI tool like Qodana CLI or Qodana Docker image.
{id="local-analysis"}


**N**

**Native mode** is an option to analyze code without using a Docker engine. Available either locally or using GitHub Actions.
{id="native-mode"}

**P**

**Problem** is an inspection rule violation in a specific code location that was detected by [%product%](#qodana) and that may deteriorate software quality.

**Profile** is a selection of [%product%](#qodana) inspections for a specific purpose.

**Project** is a codebase analyzed by [%product%](#qodana) using inspections.

**Project setup** is a [%cloud%](#qodana-cloud) project configuration, analyzing a source code repository.

**Project token or %product% token** is a [combination of characters](project-token.md) used to authorize someone to use a %product% project.

**Q**

**%product%** is a tool used for static analysis of code. Includes various components, such as %cloud% and %product% CLI.
{id="qodana"}

**%cloud%** is a cloud-based tool that manages %product% licenses, aggregates analysis reports and manages access to them.
{id="qodana-cloud"}

**%cloud% GitHub App** is a tool that integrates %cloud% with GitHub Actions and enables %cloud% to receive analysis information from GitHub.

**%cloud% organization** groups teams and projects in %cloud%. Also manages licenses and other %cloud% [features](features.topic).

**%cloud% project** groups analysis reports in %cloud%.

**%cloud% team** groups projects in %cloud%. Also manages user access.

**%premlite%** is %cloud% [deployed on user's servers](shl-introduction.md). Currently, this can be performed using Kubernetes or Docker images.


**S**

**Setup instructions** are instructions showing how a user can deploy %product% for local analysis or in a CI/CD pipeline of their choice.
